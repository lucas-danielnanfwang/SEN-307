# Lab 4 Notes: DML and Referential Integrity

In Part 4 I got **Error 1451: Cannot delete or update a parent row: a foreign key constraint fails** when I tried to delete the "Library and Information Science" department. MySQL refuses because the `Student` table has a row (Transfer Student) whose `dept_id` still points to that department. If the department were deleted, that student would reference a department that no longer exists, an "orphan" record, so the foreign key constraint protects the integrity of the data. I fixed it the correct way: first I used `UPDATE` to reassign the dependent student to the Software Engineering department, and then the `DELETE` succeeded, leaving 5 departments with the student moved rather than lost. Another fix would have been to define the foreign key with `ON DELETE CASCADE`, which automatically deletes the dependent students (risky, as data is lost), or `ON DELETE SET NULL`, which keeps the student but clears their department (this needs `dept_id` to allow NULL). I could also have deleted the student first, but that loses the record.
